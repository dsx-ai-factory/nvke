# nke-controller

![Version: 0.0.0](https://img.shields.io/badge/Version-0.0.0-informational?style=flat-square) ![Type: application](https://img.shields.io/badge/Type-application-informational?style=flat-square) ![AppVersion: 0.0.0](https://img.shields.io/badge/AppVersion-0.0.0-informational?style=flat-square)

A Helm chart to deploy the NVKE controller service

## Renamed values

Two keys were renamed to the `nvke` prefix. The old names are no longer read,
and setting either one **fails the render** with an error naming its
replacement — Helm would otherwise drop an unknown key silently and leave the
setting at its default.

| Old key              | New key                          |
| -------------------- | -------------------------------- |
| `nkeOIDCAuth`        | [`nvkeOIDCAuth`](#values)        |
| `nkeSystemNamespace` | [`nvkeSystemNamespace`](#values) |

The sub-keys are unchanged, so migrating is a rename of the top-level key:
move `create` and `annotations` from `nkeSystemNamespace` to
`nvkeSystemNamespace`, and `enabled`, `tenantRbacName`, `issuerURL`,
`discoveryURL` and `caBundleSecret` from `nkeOIDCAuth` to `nvkeOIDCAuth`.

## Upgrading an existing site: the management namespace

`nvkeSystemNamespace.name` defaults to `nvke-system`. A site installed before
that value existed holds its tenant-access Secrets — the per-cluster
`<cluster>-kubeconfig`, `<cluster>-admin-kubeconfig` and trust-bundle Secrets —
and its Cluster API objects in `nke-system`.

**Pin the old name before upgrading such a site:**

```yaml
nvkeSystemNamespace:
  name: nke-system
```

Unlike the label keys, the old namespace is not also read. Upgrading without the
pin does not fail: the chart creates `nvke-system`, moves the Roles and
RoleBindings into it, and the controller republishes there. What is left behind
is everything already in `nke-system`, including the kubeconfig Secrets Cluster
API and `nvkectl get kubeconfig` resolve by name.

`nvkectl get kubeconfig` reads `nvke-system` and then `nke-system`, so it keeps
working either way; `--namespace` names one outright.
